# Engineering Operations

## UI Foundation

Use native AppKit controls and semantic colors. General selects system, Light or Dark appearance through `NSApp.appearance` (`nil`, `.aqua`, `.darkAqua`), restored before constructing the UI and applied immediately to existing windows and glass materials. No external UI foundation is installed. The 450 × 520 pt tray uses `NSGlassEffectView` behind a macOS 26 availability check and `NSVisualEffectView` on older supported systems. Keep thumbnail colors intact. The product is a phone-to-Mac relay; the receiver accepts images, text snippets, web links and arbitrary files up to 50 MB per item. The current tray still shows images only; non-image browsing and interaction belong to the next UI delivery. The About card uses `Your phone-to-Mac drop zone` / `从手机到 Mac 的随手中转`.

The tray uses a fixed three-column masonry layout; the Text filter switches to a single full-width column. Cache image height/width ratios before layout; text, link and file cards use fixed proportions, and single-column text cards use a fixed height. Glass filter capsules sit inside the 24 pt top margin, list All followed by Images, Text, Links and Files with counts, hide types without items and default to All; content scrolls beneath them. `AnyDockCore.TrayContents` owns filtering, counts, the switch back to All when a new arrival is hidden by the current filter, and the trash scope. `MasonryCollectionLayout` uses the pure `AnyDockCore.MasonryLayout` shortest-column placement, preferring the leftmost column on ties. Image heights are capped at 2.5 times the column width and capped images show their top portion with aspect fill. The layout owns the 24 pt top/side margins, 10 pt inter-image spacing and scrollable bottom inset beneath the floating controls.

Keep native `NSCollectionView` click/modifier and rubber-band selection. Only card rectangles start selection or dragging; gaps and margins start rubber-band selection. Selected items have an accent border and corner checkmark. The latest receipt has a separate accent time capsule and soft outline, which can coexist with selection. Every card type shares the selection border, checkmark, latest-receipt highlight and time capsule. Image cards are unchanged. Text cards show the first lines and, in the single-column Text filter, a character count. Link cards show the domain and the URL as the title, since `.webloc` files carry no title. File cards show a type badge, the original filename and size, and an asynchronous `QLThumbnailGenerator` thumbnail that starts as the workspace file icon; plain-text files show their first lines in a monospaced font instead. Dragging gives images and files as the original file, text as plain text, and links as the URL plus the `.webloc` file. Command-C copies images as file plus PNG, text and links as plain values, and files as the file. Time capsules overlay the lower-left of each card, show `HH:mm` today or month/day otherwise, and expose the complete timestamp on hover. Folder sits at the left of the floating bottom controls; the optional selection count, trash and Settings controls sit at the right. Preserve button accessibility labels and tooltips. Configuration and listener errors belong in Settings. The empty tray shows a tray icon, `Nothing received yet` / `还没有收到内容` and localized guidance to share content on the iPhone and choose this Mac’s shortcut, without configuration or listener errors.

Space or double-click opens `QLPreviewPanel` for the selected files; arrows navigate the preview set and Space closes it. Keep the standard `acceptsPreviewPanelControl` / `beginPreviewPanelControl` / `endPreviewPanelControl` lifecycle. Hold the tray open while Quick Look is shown and preserve selection when only the preview closes. Copy and Finder reveal use the selected originals; dragging exports original-file URLs and closes the tray on a successful drop.

The trash button always opens a transient confirmation anchored above it. With a selection, the title is `将 N 项移到废纸篓？` and the action is `将 N 项移到废纸篓`. With no selection, only the items in the current filter are targeted and the title names the type and count, for example `将全部 N 个文件移到废纸篓？`; under All the action is `全部移到废纸篓`. English uses plural rules for every count. Escape and outside clicks cancel; the tray stays open while the confirmation is shown and after it closes. Command-Delete and the context menu recycle selected files without confirmation. Keep presentation held through confirmation closure and recycling. Limit requests to the current receive folder's `ImageStore.list` set, call `NSWorkspace.recycle`, then reload the list and report failures with remaining images visible.

New receipts of every type reveal the tray and scroll into view; when the General option to copy new items is on, each arrival is also placed on the clipboard (images as file plus PNG, text and links as plain values, files as the file). The option is off by default and stored in UserDefaults as `copyNewItems`; an open tray updates in place. Loading existing history does not reveal it. Every manual opening rereads the receive folder through `reloadImages`, reflecting files removed or restored in Finder without live folder watching. Automatic opening for a new receipt skips the extra reload. The outer popover's `popoverDidClose` clears selection and updates the controls for the next opening; closing only Quick Look or the trash confirmation does not clear it.

## Settings and shortcut setup

Settings uses native toolbar tabs ordered General, Connection and Receiving, with General selected initially. Content uses grouped inset sections with separators and footnotes.

- **General:** an off-by-default switch that copies each new item to the clipboard and system/Light/Dark appearance; app-local system/English/Simplified Chinese language selection with a restart notice and Restart Now action; immediate login startup with errors in General; an app identity card and Quit. The restart helper waits for the current process to exit before reopening the same app bundle.
- **Connection:** one-step named AirDrop setup, plus manual receive-address copying, masked connection-key copying and generic shortcut export. The shortcut name persists immediately in UserDefaults and defaults to localized `Send to ` / `发送到 ` plus `Host.current().localizedName`, falling back to localized `Send to Mac`. Saved custom names are not translated or replaced. Name validation runs before signing. Each Mac supplies a separate named shortcut, so its entry can be distinguished in the iPhone Share Sheet. There is no Apply button or listener status in this tab.
- **Receiving:** listener status and failures, a save-folder path consistently abbreviated with `~`, and port edits. Only this tab stages changes. Its bottom Apply button is enabled when the selected folder or port differs from the applied configuration, except while applying. Port validation remains 1024–65535; changing folders never moves or deletes existing originals.

`ShortcutInstaller` personalizes the bundled unsigned template with the applied receive address, key and chosen name. It writes sensitive output only in temporary storage, signs with `/usr/bin/shortcuts sign --mode anyone`, and supplies the signed file to the AirDrop sharing service. Sharing completion or failure cleans up temporary files; cleanup failures are reported and can be retried. Never log the key, print sensitive signing output or copy personalized files into the source tree or bundle. Settings explains that system signing submits a copy to Apple for validation and that the shortcut should be sent only to the user's own iPhone. On the iPhone, the recipient adds the shortcut without entering connection values. Signing or AirDrop failures leave the manual path usable. The generic manual export retains its import questions. Resend or update the iPhone shortcut after changing the receive port.

The user-provided V2 app icon is retained as `Resources/AppIcon.icns`, directly using Apple-rendered macOS representations. `Resources/Brand/AnyDockIcon.png` is the rounded, padded compatibility export used by the Settings About card. `BrandIcon.swift` loads the 18px and 36px menu bar PNGs at 18pt and marks the image as a template. `scripts/build.sh` copies these assets into the app bundle. Asset provenance and replacement instructions are in `Resources/Brand/README.md`; replace approved rendered exports directly rather than regenerating the icns from the About-card PNG.

### Multi-item shortcut behavior

The updated shortcut declares concrete Share Sheet input classes for images, plain/rich text, URLs/Safari webpages, generic files, PDF and media; the abstract `WFContentItem` base class is not an input match. Share Sheet input is sent one item at a time; without Share Sheet input, it reads the clipboard instead. Each item is a separate authenticated request. A size precheck skips items above 50 MB and counts them as failures. HTTP error responses such as 401, 413 and 415 are counted by category, then the loop continues. All value conditions explicitly receive a Text action output and use text comparison values, including HTTP status codes. The no-input guard retains the has-no-value operator. Size preflight converts the byte-count quotient into an integer flag before a text equality check, so it does not rely on mixed numeric/dictionary conditional typing. One final notification titled 随手坞 reports `成功 N 项` when everything succeeds; with failures it reads `成功 N 项，失败 M 项：` followed only by the reasons whose count is not zero, for example `超过 50MB 1 项`. Each reason is skipped with a text comparison against `0` and appended by text concatenation. There are no per-item confirmation alerts. Users must resend and add the updated shortcut, including personalized shortcuts. Both the generic signed resource and the runtime unsigned template use the same generator.

Transport errors have a different boundary: timeouts, disconnection and an unreachable Mac may stop the whole shortcut with the standard iOS error. Continuing after those errors is not promised. There is no third-party action app or persistent upload queue. Phone acceptance must include sending several items with Wi-Fi disconnected, confirming that the shortcut stops and reports an error and that no incomplete files appear on the Mac. Mixed photos/files, clipboard text/links, over-limit skipping and recoverable HTTP errors also require phone acceptance; generated-structure checks do not establish them.

## Receiving and storage

`POST /upload` retains `X-SnapDock-Key` authentication and the old raw-image body format. New requests can specify `X-AnyDock-Type` (`image`, `text`, `link`, `file`) and a percent-encoded UTF-8 `X-AnyDock-Filename`. Plain text uses `text/plain; charset=utf-8`, links use `text/uri-list`, and generic files use `application/octet-stream`. A filename makes text content a file; images are still recognized from actual ImageIO-supported contents, not a claimed extension. Text snippets require UTF-8 and links accept only HTTP/HTTPS URLs. The receiver validates the length before buffering a full body, with a 50,000,000-byte payload cap, four concurrent connections and a 45-second connection deadline. Arbitrary files include videos within the same cap; there is no dedicated video model or directory.

New arrivals go into `Images/`, `Text/`, `Links/` or `Files/`, created on first use. Snippets become `.txt`, links become `.webloc`, and generic files retain the sanitized original filename and extension after a unique `AnyDock-` prefix. Names reject paths and control characters, remove leading/trailing dots and replace colons. Existing flat `SnapDock-*` and `AnyDock-*` images stay in place. Fresh configurations default to `~/Downloads/AnyDock`; an existing configured receive path and connection key are preserved.

`ImageStore.list` returns typed `ReceivedItem` values; `ReceivedKind` has image, text, link and file cases. Files expose `isPlainText` for the monospaced preview. The tray lists and recycles the 120 newest items of all kinds from `ImageStore.list`; `listImages` remains as the image-only adapter. Every list ignores unrelated names, symlink files and symlink category directories. Only listed generated items are eligible for recycling.

Storage pins root and category directory descriptors without following category symlinks. Staging creation, quarantine writes/verification, cleanup and exclusive atomic publication use descriptor-relative operations. The category identity is checked before and after publication; replacement refuses the upload and cleans its own file through the pinned descriptor. Non-images receive quarantine on the open staging file before publication. The `com.apple.quarantine` attribute must be present before success is reported. Failed or incomplete uploads cannot publish a partial item, and existing files are never overwritten. Files are never opened or executed automatically. Tests use temporary directories, fixture credentials and private localhost listeners, including truncated requests and symlink escape attempts.

## Localization

English is the development language. The executable target declares `.process("Resources")` and `defaultLocalization: "en"`; these are localization resource declarations, not dependencies. Load UI text through `L10n.text` and `Bundle.module`. The `en.lproj` and `zh-Hans.lproj` resources contain strings and `.stringsdict` count/plural rules, covering the tray, Settings, shortcut preparation errors and localized default shortcut names. System errors retain the platform's localized descriptions. The generic shortcut resource and Python-generated shortcut-internal prompts remain Chinese.

The app's `Info.plist` declares both supported localizations. `scripts/build.sh` embeds the SwiftPM resource bundle and copies each localized `InfoPlist.strings` into the app's resource directory, so privacy prompts and bundle language negotiation work outside the build tree. Keep new strings and placeholders consistent across both localizations.

Language selection reads only the app's persistent preference domain, not inherited global `AppleLanguages`. English stores `["en"]`, Simplified Chinese stores `["zh-Hans"]`, and Follow System removes the app-local key. This preference is read by Foundation on the next launch; Settings compares it with the launch selection to show the restart action. The preference test uses an isolated suite and never changes user preferences.

## Build and run

Use `./scripts/build.sh`, `./scripts/run.sh`, `./scripts/lint.sh` and `./scripts/test.sh`. Use a compatible Swift 6 compiler and an SDK containing the macOS 26 glass APIs; the development toolchain is Xcode 27.2 / Apple Swift 6.4.2. The selected Xcode compiler builds the Swift package and the build script creates and ad-hoc signs `dist/AnyDock.app`. Build products are disposable. No dependency installation is required. Keep the app bundle identifier `studio.alex.snapdock`.

## Operation

The app runs as an accessory with no Dock icon. Quit through Settings. No LaunchAgent is installed. Login startup is a user-controlled setting in the app. The default port is 8765. Debug with Console using the AnyDock process, or launch the built executable from a terminal. Do not expose authentication tokens in logs.

To open the configuration window on a fresh debug launch, use `open dist/AnyDock.app --args --settings`. Reopening an already-running app also opens Settings. Use `--tray` instead of `--settings` for direct inspection of the menu bar popover during authorized local UI verification.

Only files generated by AnyDock in the selected inbox are shown, using the same `ImageStore.list` set that limits recycling. App configuration and received originals remain outside the checkout. Receiver configuration uses Application Support; the copy-new-items and personalized shortcut name preferences use UserDefaults. Never overwrite or automatically delete received originals.

## Merging pull requests

`.github/workflows/auto-merge.yml` is the only merge path; authors do not merge their own PRs. It runs when a review is submitted, when CI completes for a PR and when the `needs-acceptance` label is removed. It squash-merges with `--delete-branch --match-head-commit` only when all of these hold:

- the PR's current head is the commit that was approved;
- no reviewer's latest decision is `CHANGES_REQUESTED`;
- only reviewers whose repository permission (`collaborators/{login}/permission`) is write, maintain or admin count, for both approvals and change requests; anyone can submit a review on this public repository, and `authorAssociation` cannot be used because private organization members appear as `NONE` to the workflow token;
- the PR has no `needs-acceptance` label;
- CI has run on that head and every other check succeeded.

While checks are running or the PR waits for acceptance, the workflow exits without merging and a later event retries. When a check fails, it comments once per approved commit with the failing checks. Open UI-bearing PRs with the `needs-acceptance` label; the architect removes it after the user accepts the UI. Merges made with `GITHUB_TOKEN` do not start push workflows, so the workflow dispatches `ci.yml` on `main` after merging. Branch protection is configured separately in the repository settings.

Review and label events (`pull_request_review`, `pull_request: unlabeled`) run the workflow definition from the PR's merge ref, while CI completion (`workflow_run`) runs the definition on `main`. A PR whose branch predates a change to `auto-merge.yml` may therefore get no run, not even a skipped one, when it is approved or its label is removed. Update the branch from `main` (for example with GitHub's Update branch) so the next review or label event runs the current workflow; the next CI completion also retries the merge.

## Scope of evidence

The UI rules above describe the current product behavior. Local build and automated checks do not establish visual interaction, iPhone import/upload or compatibility with a particular chat client. Those outcomes require their own acceptance evidence. Report actual validation results and distinguish automated checks from hands-on acceptance.

## Rename compatibility

Keep the `studio.alex.snapdock` bundle identifier and Logger subsystem, all UserDefaults keys, `Application Support/SnapDock` configuration directory and existing configured receive paths unchanged; fresh configurations use `~/Downloads/AnyDock`. New files use `AnyDock-`; `ImageStore.list` must also include legacy `SnapDock-` images, and recycling must use that same set.
