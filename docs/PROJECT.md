# Engineering Operations

## UI Foundation

Use native AppKit controls and semantic colors. General selects system, Light or Dark appearance through `NSApp.appearance` (`nil`, `.aqua`, `.darkAqua`), restored before constructing the UI and applied immediately to existing windows and glass materials. The tray popover would otherwise take its appearance from the menu bar window it is anchored to, which ignores `NSApp.appearance`, so `AppAppearance.follow` observes `NSApp.effectiveAppearance` and copies it to `popover.appearance`; this covers Light, Dark, Follow System and system changes while the tray is open. Self-drawn layer colors refresh in `viewDidChangeEffectiveAppearance`. No external UI foundation is installed. The 480 × 640 pt tray's outer shape and background come only from `NSPopover`; the root view draws no corner radius or material of its own. Floating tray controls use `NSGlassEffectView` behind a macOS 26 availability check and `NSVisualEffectView` on older supported systems. Keep thumbnail colors intact. The product is a phone-to-Mac relay; the receiver accepts images, text snippets, web links and arbitrary files up to 50 MB per item. The current tray still shows images only; non-image browsing and interaction belong to the next UI delivery. The About tab uses the README tagline `From iPhone to Mac, in one easy hand-over.` / `从 iPhone 到 Mac，随手一递。`.

The tray uses a fixed four-column masonry layout; the Text filter switches to a single full-width column. Image card heights come from the header ratio returned by `InboxStore.list`, so the later preview fits the same frame; text, link and file cards use fixed proportions, and single-column text cards use a fixed height. `TrayScopeBar` is a single 36 pt glass capsule with a 4 pt inner inset, shown whenever the tray has items, at the same 24 pt top and left margin as the cards. It shares the top row with the Folder and Settings icon buttons, which form one capsule group of the same 36 pt height and 4 pt inset at the 24 pt right margin (one `NSGlassEffectView` on macOS 26, the same-shaped material capsule on 14–25). The filter bar keeps at least 8 pt from the group and scrolls only when the segments do not fit in the remaining width. Its segments list All followed by Images, Text, Links and Files with counts and 12 pt horizontal padding, hide only types without items and default to All. The selected segment sits on a neutral capsule indicator (white in light appearance, translucent white in dark) that slides with a 0.2 s animation. When the segments are wider than that space, the bar scrolls horizontally and fades 32 pt at the edges that have more content. The layout's top inset is the bar margin, the bar height and a 16 pt gap, so the first row rests fully below the bar. Content scrolls directly under the top row and the bottom floating controls, which stay on top. New or changed spacing in the tray uses the local `Space` scale of 4, 8, 12, 16, 24 and 32 pt, and `TrayMetrics` holds the tray's sizes; both take Pocky's values without depending on Pocky. The scroll view does not adjust its content insets automatically, and the layout measures its width from the clip view. `AnyDockCore.TrayContents` owns filtering, counts, and the switch back to All when a new arrival is hidden by the current filter. `TrayViewModel` (no AppKit) holds the tray state: the received items and current filter, the selected URLs in visible order, the latest receipt, the dragged items and whether recycling is running. User intents are its methods (`select`, `toggleSelectAll`, `receive`, `replace`, `beginDrag`/`endDrag`, `trashDraggedItems`, `recycleSelection`), and it loads and recycles through an injected `TrayInbox`; `AppDelegate` supplies one backed by `InboxStore.list` for the current receive folder. Tray views and `TrayViewController` subscribe to its publishers to render and forward native collection selection and user actions to it; they do not keep their own copy of this state. `TrayViewController` only composes the components and routes their events: `TrayHeaderView` (filter bar, Folder and Settings), `TrayCollectionController` (cards, native selection, dragging and lazy previews), `TrayFooterView` (selection and drop capsule, release watching and clipboard bar placement), `TrayEmptyStateView` and `TrayQuickLookController`. Tray sizes, card spacing and column counts live in `TrayMetrics`, shadows in the `TrayElevation` roles and glass surfaces in `TrayGlass`. `MasonryCollectionLayout` uses the pure `AnyDockCore.MasonryLayout` shortest-column placement, preferring the leftmost column on ties. Image heights are capped at 2.5 times the column width and capped images show their top portion with aspect fill. The layout applies the `TrayMetrics` 24 pt top/side margins, 12 pt spacing between cards in both directions and scrollable bottom inset beneath the floating controls; `TrayViewModel.isSingleColumn` decides the single-column Text layout.

Keep native `NSCollectionView` click/modifier and rubber-band selection. Only card rectangles start selection or dragging; gaps and margins start rubber-band selection. Selected items have a solid accent border and corner checkmark. The latest receipt is marked only by a 6 pt accent dot before its time, so it cannot be confused with selection. Image cards show the image without a frame, the uppercase extension at the top-left and a translucent dark time capsule at the lower-left. Text, link and file cards are Polaroid cards: an off-white frame (8 pt padding, small corner radius, soft shadow and a hairline border) with a preview area on top and a caption strip below. Polaroid cards have a single caption line led by the 6 pt latest dot: files show the middle-truncated filename, text and links show the receipt time. The caption is never compressed vertically; previews, file thumbnails (`NSImageView` compression resistance is low, otherwise its intrinsic size equals the thumbnail's pixel size and squeezes the caption) and link domains give up height first. Text previews show the text; link previews show the bold domain on one middle-truncated line and the URL below; file previews show an asynchronous `QLThumbnailGenerator` first-page thumbnail that starts as the type icon, or the first lines in monospace for plain-text files. Every card has an extension badge at the top-left of its preview: PDF red, plain-text files dark gray, text snippets gray (`TEXT`), links blue (`URL`) and other files neutral with their real extension. A file saved without an extension is identified by its `%PDF-` header, so its badge, icon and Quick Look thumbnail request use the PDF type. Dragging gives images and files as the original file, text as plain text, and links as the URL plus the `.webloc` file. Command-C copies images as file plus PNG, text and links as plain values, and files as the file. Times show `HH:mm` today or month/day otherwise, and every card exposes the complete timestamp on hover. `TrayDropZone` is a floating, horizontally centered glass capsule that takes no layout space and never changes the content frame: it sits 8 pt above the clipboard bar, or 16 pt above the tray's bottom edge while the clipboard bar is hidden. It is hidden with no selection and shows `%d selected` / `已选 %d 项` for several items. With one item it shows that item's detail: files `name · size · time` with only the name middle-truncated, images the uppercase extension, size and time (never the stored filename), text `N chars · time` / `N 字 · time` and links the middle-truncated full URL. While dragging it always shows the red drop target. Empty detail segments are skipped without extra separators, and an empty detail hides the capsule. The detail label's horizontal compression resistance is `dragThatCannotResizeWindow`: above its hugging so the capsule width is not ambiguous, below the window size priorities so a long name truncates instead of widening the tray. Preserve button accessibility labels and tooltips. Configuration and listener errors belong in Settings. The empty tray shows a tray icon, `Nothing received yet` / `还没有收到内容` and localized guidance to share content on the iPhone and choose this Mac’s shortcut, without configuration or listener errors.

Space or double-click opens `QLPreviewPanel` for the selected files; arrows navigate the preview set and Space closes it. Keep the standard `acceptsPreviewPanelControl` / `beginPreviewPanelControl` / `endPreviewPanelControl` lifecycle. Hold the tray open while Quick Look is shown and preserve selection when only the preview closes. Copy and Finder reveal use the selected originals; dragging exports original-file URLs and closes the tray on a successful drop outside the tray. Single-clicking a filter segment only switches the filter; every even mouse click count (`NSEvent.clickCount` 2, 4, …, so a rapid second double-click toggles once instead of twice; odd counts act as single clicks, which keep the selection) selects every card visible in that filter, or clears the selection when all of them are already selected (never an inversion), without reloading when the filter is already selected.

There is no trash button. When a drag of tray cards begins, the controller records the dragged items (the selection or a single unselected card) and `TrayDropZone` shows red `Drop here to move to Trash` / `拖到这里放入废纸篓`; it accepts only drags whose source is the tray collection, fills with `systemRed` while targeted and returns `.delete` (the collection allows copy and delete locally, copy only externally). Dropping there recycles exactly the dragged items without confirmation, clears the selection and keeps the tray open; the drag end does not close the tray. The red target disappears as soon as the mouse button is released: a drop on it hides the target before recycling starts, and a release elsewhere hides it while the system's slide-back animation is still running (the controller watches `NSEvent.pressedMouseButtons` during the drag). The drag end then restores the selection detail. Command-Delete and the context menu recycle selected files without confirmation. Keep presentation held through recycling. Limit requests to the current receive folder's `InboxStore.list` set, call `NSWorkspace.recycle`, then reload the list and report failures with remaining images visible.

New receipts of every type reveal the tray and scroll into view; when the General option to copy new items is on, each arrival is also placed on the clipboard (images as file plus PNG, text and links as plain values, files as the file). The option is off by default and stored in UserDefaults as `copyNewItems`; an open tray updates in place. Loading existing history does not reveal it. Every manual opening rereads the receive folder through `reloadItems`, reflecting files removed or restored in Finder without live folder watching. Automatic opening for a new receipt skips the extra reload. The outer popover's `popoverDidClose` clears selection and updates the controls for the next opening; closing only Quick Look does not clear it.

## Clipboard history

`ClipboardMonitor` owns a pure `ClipboardHistory` (app target, `Sources/AnyDock/Clipboard`) of at most 4 plain-text entries, newest first; a text equal to the newest entry is not added again. While the General switch `Keep last 4 clipboard texts` / `保留最近 4 条剪贴板文本` (UserDefaults `keepClipboardHistory`, default on) is on, a main-run-loop `Timer` with a 0.5 s interval and 0.25 s tolerance compares `NSPasteboard.general.changeCount` and reads contents only after it changes. It records `.string` content unless the item also carries `.fileURL` or `org.nspasteboard.ConcealedType`; `org.nspasteboard.TransientType` is deliberately recorded, because voice input may mark its text that way. Text AnyDock copies itself is recorded too. Copying the connection key in Settings also declares `org.nspasteboard.ConcealedType`, so the key is never recorded by this history or by other clipboard managers. Every tray clipboard write, including automatic copying of new items, first polls synchronously so text another app just wrote is captured before it is replaced. Copying a clip again marks the resulting change as seen so it does not add a duplicate. History lives only in memory: it is never written to disk or logs, is cleared on quit and is cleared and stops polling when the switch is turned off. Turning it on starts from the current clipboard without recording it.

`ClipboardBar` is a separate attachment, not tray content: it never appears in `TrayScopeBar`, filters, counts, selection, Quick Look or `TrayDropZone`. It uses the same glass surface as the other floating controls (`NSGlassEffectView` on macOS 26, the material fallback on 14–25); its outer edges align with the cards' 24 pt side margins, it sits 16 pt above the tray's bottom edge, and its header and cell row use 12 pt horizontal padding. It is hidden while the history is empty. Collapsed, the default at every tray opening, it is one capsule row: clipboard icon, `Clipboard · N items` / `剪贴板 · N 条`, `Clear` / `清空` and an up chevron; clicking the row or the chevron expands it. Expanded, the header reads `Clipboard · Double-click to copy` / `剪贴板 · 双击复制` with Clear and a down chevron; clicking the header row anywhere except Clear, or the chevron, collapses it, and Clear only clears without toggling, above one row of four equal-width cells that never scroll. Each cell shows the first two lines of its text, truncated, and a relative time; the newest is at the left with the 6 pt accent dot. Double-clicking a cell (or the accessibility press action) copies its text without adding a duplicate; dragging a cell outside the app gives plain text, and the tray's drop area never accepts it. Expanding and collapsing animate the bar's height over 0.15 s together with the tray content view's layout, and the masonry layout adds the bar's height plus 8 pt to its bottom inset so the last row stays reachable above it. Escape collapses the expanded bar before it clears the selection. Clear empties the history immediately without confirmation, which hides the bar and restores the full content inset. Tests use private `NSPasteboard(name:)` instances, never the general pasteboard.

## Wake shortcut

General's Keyboard section has a `Wake shortcut` / `唤醒快捷键` recorder and a Clear button; no shortcut is set by default. Clicking the recorder starts recording (`Type shortcut…` / `请按下快捷键…`); the next key with ⌘, ⌥ or ⌃ is saved immediately, Esc without those modifiers cancels, and a key with no modifier or ⇧ alone is rejected with a localized hint while recording continues. Recording also ends when the recorder loses focus or the Settings window stops being key. The recorder shows standard symbols in Apple order (⌃⌥⇧⌘) followed by the key name, using the current keyboard layout for character keys. The shortcut is stored in UserDefaults `wakeHotKey` as `keyCode` (Carbon virtual key) and `modifiers` (`NSEvent.ModifierFlags` raw value, limited to ⌃⌥⇧⌘); it is a new key and does not affect other preferences.

`HotKeyCenter` registers it with Carbon `RegisterEventHotKey` on the application event target, which needs no Accessibility permission; do not use `NSEvent` global monitors. Every change unregisters the previous registration first. While recording, the registration is suspended so pressing the current shortcut reaches the recorder instead of the tray, and the saved shortcut is registered again when recording ends. When registration of a new shortcut fails, it is not saved, the previous shortcut is registered again and General shows `%@ is already in use…` / `%@ 已被 macOS 或其他 App 占用…`; a saved shortcut that fails at launch shows the same message. Carbon reports only conflicts it knows about; a combination already taken by a system shortcut can register without error and never fire. Pressing the shortcut runs the same toggle as clicking the menu bar icon: it closes Quick Look when the tray is held, closes an open tray, or shows the tray below the icon, activates AnyDock, rereads the receive folder and makes the collection view first responder so arrows, Space, ⌘C and Esc work immediately.

## Settings and shortcut setup

Settings uses native toolbar tabs ordered General, Connection, Receiving and About, with General selected initially. Content uses grouped inset sections with separators. Footnotes are kept only where users would otherwise make a mistake or worry: security, privacy or a required action. Hidden rows, such as the language restart row, are hidden as whole stack rows so they leave no gap.

- **General:** sections in this order: Startup with immediate login startup and its errors; Personalization with system/Light/Dark appearance and app-local system/English/Simplified Chinese language selection, followed by a restart notice and Restart Now action; Tray with the off-by-default switch that copies each new item to the clipboard and the on-by-default switch that keeps the last 4 clipboard texts in memory, noted `Kept in memory only and cleared when you quit.` / `仅存在内存中，退出即清空。`; Keyboard with the `Wake shortcut` / `唤醒快捷键` recorder (see below). The restart helper waits for the current process to exit before reopening the same app bundle.
- **Connection:** one-step named AirDrop setup, plus manual receive-address copying, masked connection-key copying and generic shortcut export. The shortcut name persists immediately in UserDefaults and defaults to localized `Send to ` / `发送到 ` plus the computer name from `SCDynamicStoreCopyComputerName`, falling back to localized `Send to Mac`. Saved custom names are not translated or replaced. Name validation runs before signing. Each Mac supplies a separate named shortcut, so its entry can be distinguished in the iPhone Share Sheet. There is no Apply button or listener status in this tab.
- **Receiving:** listener status and failures, a save-folder path consistently abbreviated with `~`, and port edits. Only this tab stages changes. Its bottom Apply button is enabled when the selected folder or port differs from the applied configuration, except while applying. Port validation remains 1024–65535; changing folders never moves or deletes existing originals.
- **About:** centered app icon, `AnyDock` / `随手坞`, `Version %@ (%@)` / `版本 %@ (%@)` from the bundle's `CFBundleShortVersionString` and `CFBundleVersion` (hidden when the bundle has neither), the README tagline, `GitHub Project` / `GitHub 项目` and `Author @Cunqi` / `作者 @Cunqi` buttons opening https://github.com/alex-coding-studio/AnyDock and https://github.com/Cunqi through `NSWorkspace`, `© 2026 Cunqi · MIT License`, and Quit at the bottom.

The receive address is `http://<LocalHostName>.local:<port>/upload`, where the Bonjour name comes from `SCDynamicStoreCopyLocalHostName`; without one it falls back to the first IPv4 interface address and then `localhost`. Never use `ProcessInfo.hostName` or `NSHost` for it: they resolve DNS synchronously and once stalled the main thread for about 30 seconds at launch, delaying the receiver. The default shortcut name uses `SCDynamicStoreCopyComputerName`. The Settings window builds its tabs on first display rather than at launch. `ShortcutInstaller` personalizes the bundled unsigned template with the applied receive address, key and chosen name. It writes sensitive output only in temporary storage, signs with `/usr/bin/shortcuts sign --mode anyone`, and supplies the signed file to the AirDrop sharing service. Sharing completion or failure cleans up temporary files; cleanup failures are reported and can be retried. Never log the key, print sensitive signing output or copy personalized files into the source tree or bundle. Settings explains that system signing submits a copy to Apple for validation and that the shortcut should be sent only to the user's own iPhone. On the iPhone, the recipient adds the shortcut without entering connection values. Signing or AirDrop failures leave the manual path usable. The generic manual export retains its import questions. Resend or update the iPhone shortcut after changing the receive port.

The user-provided V2 app icon is retained as `Resources/AppIcon.icns`, directly using Apple-rendered macOS representations. `Resources/Brand/AnyDockIcon.png` is the rounded, padded compatibility export used by the Settings About tab. `BrandIcon.swift` loads the 18px and 36px menu bar PNGs at 18pt and marks the image as a template. `scripts/build.sh` copies these assets into the app bundle. Asset provenance and replacement instructions are in `Resources/Brand/README.md`; replace approved rendered exports directly rather than regenerating the icns from the About-card PNG.

### Multi-item shortcut behavior

The updated shortcut declares concrete Share Sheet input classes for images, plain/rich text, URLs/Safari webpages, generic files, PDF and media; the abstract `WFContentItem` base class is not an input match. Share Sheet input is sent one item at a time; items that remain files after the link and text checks are named `<Get Name>.<File Extension>` from the Get Details of Files `File Extension` property, because Get Name drops the extension; links and text never run these file-property actions. Shortcuts exposes no MIME type for files, so they keep `application/octet-stream` and the receiver infers the type from content; without Share Sheet input, it reads the clipboard instead. Each item is a separate authenticated request. A size precheck skips items above 50 MB and counts them as failures. HTTP error responses such as 401, 413 and 415 are counted by category, then the loop continues. All value conditions explicitly receive a Text action output and use text comparison values, including HTTP status codes. The no-input guard retains the has-no-value operator. Size preflight converts the byte-count quotient into an integer flag before a text equality check, so it does not rely on mixed numeric/dictionary conditional typing. One final notification titled 随手坞 reports `成功 N 项` when everything succeeds; with failures it reads `成功 N 项，失败 M 项：` followed only by the reasons whose count is not zero, for example `超过 50MB 1 项`. Each reason is skipped with a text comparison against `0` and appended by text concatenation. There are no per-item confirmation alerts. Users must resend and add the updated shortcut, including personalized shortcuts. Both the generic signed resource and the runtime unsigned template use the same generator.

Transport errors have a different boundary: timeouts, disconnection and an unreachable Mac may stop the whole shortcut with the standard iOS error. Continuing after those errors is not promised. There is no third-party action app or persistent upload queue. Phone acceptance must include sending several items with Wi-Fi disconnected, confirming that the shortcut stops and reports an error and that no incomplete files appear on the Mac. Mixed photos/files, clipboard text/links, over-limit skipping and recoverable HTTP errors also require phone acceptance; generated-structure checks do not establish them.

## Receiving and storage

`POST /upload` authenticates with `X-AnyDock-Key` and retains the old raw-image body format. New requests can specify `X-AnyDock-Type` (`image`, `text`, `link`, `file`) and a percent-encoded UTF-8 `X-AnyDock-Filename`. Plain text uses `text/plain; charset=utf-8`, links use `text/uri-list`, and generic files use `application/octet-stream`. A filename makes text content a file; images are still recognized from actual ImageIO-supported contents, not a claimed extension. Text snippets require UTF-8 and links accept only HTTP/HTTPS URLs. The receiver validates the length before buffering a full body, with a 50,000,000-byte payload cap, four concurrent connections and a 45-second connection deadline. Arbitrary files include videos within the same cap; there is no dedicated video model or directory.

New arrivals go into `Images/`, `Text/`, `Links/` or `Files/`, created on first use. Snippets become `.txt`, links become `.webloc`, and generic files retain the sanitized original filename and extension after a unique `AnyDock-` prefix. When a file's header is a PDF, PNG, JPEG, GIF, HEIC or ZIP signature, the detected type's preferred extension is appended if the name has no extension, an extension the system does not declare, a text extension, or another detectable type's extension (`report.txt` with PDF bytes becomes `report.txt.pdf`). Other known formats built on these signatures, such as `.ai`, `.heif`, `.epub` or `.docx`, keep their name, unrecognized content keeps its name, and the appended extension never changes the image decision, `Files/` placement or quarantine. Names reject paths and control characters, remove leading/trailing dots and replace colons. Existing flat `AnyDock-*` images stay in place. Fresh configurations default to `~/Downloads/AnyDock`; an existing configured receive path and connection key are preserved.

`InboxStore.list` returns typed `ReceivedItem` values; `ReceivedKind` has image, text, link and file cases. Files expose `isPlainText` for the monospaced preview. The tray lists and recycles every generated item of all kinds from `InboxStore.list`, newest first. `list` reads only metadata: file attributes, the `.webloc` URL, a 4 KB prefix to detect plain-text files, and for images the pixel size and EXIF orientation from the header (`CGImageSourceCopyPropertiesAtIndex`, width and height swapped for orientations 5–8; ratio 1 when the header has no size). It never decodes image content; the `InboxStore` actor reuses image ratios keyed by URL and modification date across tray openings. Text cards read an 8 KB prefix for the 1000-character preview; the character count in the selection detail reads the whole text only when shown. Image and file previews are generated when a card is configured for display, off the main thread (ImageIO for images, `QLThumbnailGenerator` for files), and applied only to the card still showing that URL. `TrayPreviewCache` keeps them in an `NSCache` limited by count (200) and pixel cost, keyed by URL and modification date; evicted previews are regenerated when the card reappears. Removed items and receive-folder changes bump a per-URL version so late results are discarded, and in-flight requests are deduplicated per URL with a generation check. An image that cannot be decoded keeps the gray placeholder. Every list ignores unrelated names, symlink files and symlink category directories. Only listed generated items are eligible for recycling.

Storage pins root and category directory descriptors without following category symlinks. Staging creation, quarantine writes/verification, cleanup and exclusive atomic publication use descriptor-relative operations. The category identity is checked before and after publication; replacement refuses the upload and cleans its own file through the pinned descriptor. Non-images receive quarantine on the open staging file before publication. The `com.apple.quarantine` attribute must be present before success is reported. Failed or incomplete uploads cannot publish a partial item, and existing files are never overwritten. Files are never opened or executed automatically. Tests use temporary directories, fixture credentials and private localhost listeners, including truncated requests and symlink escape attempts.

## Localization

English is the development language. The executable target declares `.process("Resources")` and `defaultLocalization: "en"`; these are localization resource declarations, not dependencies. Load UI text through `L10n.text` and `Bundle.module`. The `en.lproj` and `zh-Hans.lproj` resources contain strings and `.stringsdict` count/plural rules, covering the tray, Settings, shortcut preparation errors and localized default shortcut names. System errors retain the platform's localized descriptions. The generic shortcut resource and Python-generated shortcut-internal prompts remain Chinese.

The app's `Info.plist` declares both supported localizations. `scripts/build.sh` embeds the SwiftPM resource bundle and copies each localized `InfoPlist.strings` into the app's resource directory, so privacy prompts and bundle language negotiation work outside the build tree. Keep new strings and placeholders consistent across both localizations.

Language selection reads only the app's persistent preference domain, not inherited global `AppleLanguages`. English stores `["en"]`, Simplified Chinese stores `["zh-Hans"]`, and Follow System removes the app-local key. This preference is read by Foundation on the next launch; Settings compares it with the launch selection to show the restart action. The preference test uses an isolated suite and never changes user preferences.

## Build and run

Use `./scripts/build.sh`, `./scripts/run.sh`, `./scripts/lint.sh` and `./scripts/test.sh`. Use a compatible Swift 6 compiler and an SDK containing the macOS 26 glass APIs; the development toolchain is Xcode 27.2 / Apple Swift 6.4.2. The selected Xcode compiler builds the Swift package and the build script creates and ad-hoc signs `dist/AnyDock.app`. Build products are disposable. The app needs no dependency installation; `lint.sh` needs SwiftFormat 0.62.1 and SwiftLint 0.65.0, the versions CI pins and installs from their GitHub release binaries, and refuses other local versions. Formatting follows `.swiftformat` and `.swift-version`, and linting follows `.swiftlint.yml`; both are copied from the owner's shared iOS rules. The SwiftLint rule set adds `included` paths and a `baseline` entry, and its magic-value rules point to local Metrics roles (AnyDock does not use CXDesignKit). File and type line counts are not a gate (`file_length` and `type_body_length` stay disabled); `function_body_length` warns at 80 and fails at 200 lines. `.swiftlint-baseline.json` records the violations that existed when SwiftLint was adopted, with repository-relative paths that `scripts/portable-swiftlint-baseline.py` resolves for the current checkout; strict lint fails only on violations not in it. Keep the app bundle identifier `com.cuxiao.mac.anydock`. Enable the committed Git hooks once per clone with `git config core.hooksPath .githooks`. The pre-commit hook refuses commits on `main` and runs `./scripts/lint.sh` in check mode.

## Release

`./scripts/release.sh` produces the distributable DMG on a developer Mac; CI never runs it because it has no certificate, and lint only checks its syntax. It reads the version from `Resources/Info.plist` `CFBundleShortVersionString`, removes the previous `dist/AnyDock.app` and DMG, runs `build.sh`, then re-signs with `--force --options runtime --timestamp`: nested frameworks, dylibs, XPC services, app extensions and apps are signed innermost first (there are none today; the SwiftPM resource bundle and shortcuts are sealed as resources), then the app. It never signs with `--deep`. It verifies the signature and team, builds `dist/AnyDock-<version>.dmg` with `hdiutil` (volume `AnyDock`, the app and an `Applications` link), signs the DMG, submits it with `xcrun notarytool submit --keychain-profile … --wait`, staples and validates the ticket, and checks the DMG with `spctl -a -t open --context context:primary-signature` and the app with `spctl -a -vv`.

Defaults: identity `Developer ID Application: Cunqi Xiao (2PQ63WGMNP)`, team `2PQ63WGMNP`, notary profile `MyQuickFinderApi` (the developer account's shared notarytool keychain profile); override them with `ANYDOCK_SIGN_IDENTITY`, `ANYDOCK_TEAM_ID` and `ANYDOCK_NOTARY_PROFILE`. A missing identity stops before building. A missing or invalid notary profile stops after the signed DMG is created and prints the `xcrun notarytool store-credentials` command to run; the script never prints credentials. On a Mac without it, create a profile once with `xcrun notarytool store-credentials <profile> --apple-id <Apple ID> --team-id 2PQ63WGMNP` and an app-specific password, and pass its name through `ANYDOCK_NOTARY_PROFILE` if it differs.

The hardened runtime needs no entitlements: the app does not use JIT, unsigned executable memory, DYLD variables, non-system libraries, debugging or privacy-protected devices and data. Network listening is restricted only by the App Sandbox, which AnyDock does not use; `SMAppService` login items, launching `/usr/bin/shortcuts` and `/bin/sh` for restart, Quick Look thumbnails and AirDrop sharing need no entitlement. Add the smallest entitlement set only when a new capability requires one.

Publishing a GitHub Release, tagging and uploading the DMG are separate, user-approved steps outside the script.

## Operation

The app runs as an accessory with no Dock icon. Quit through Settings. No LaunchAgent is installed. Login startup is a user-controlled setting in the app. The default port is 8765. Debug with Console using the AnyDock process, or launch the built executable from a terminal. Do not expose authentication tokens in logs.

To open the configuration window on a fresh debug launch, use `open dist/AnyDock.app --args --settings`. Reopening an already-running app also opens Settings. Use `--tray` instead of `--settings` for direct inspection of the menu bar popover during authorized local UI verification.

Only files generated by AnyDock in the selected inbox are shown, using the same `InboxStore.list` set that limits recycling. App configuration and received originals remain outside the checkout. Receiver configuration uses Application Support; the copy-new-items and personalized shortcut name preferences use UserDefaults. Never overwrite or automatically delete received originals.

## Merging pull requests

`.github/workflows/auto-merge.yml` is the only merge path; authors do not merge their own PRs. It runs when a review is submitted, when CI completes for a PR and when the `needs-acceptance` label is removed. It squash-merges with `--delete-branch --match-head-commit` only when all of these hold:

- the PR's current head is the commit that was approved;
- no reviewer's latest decision is `CHANGES_REQUESTED`;
- only reviewers whose repository permission (`collaborators/{login}/permission`) is write, maintain or admin count, for both approvals and change requests; anyone can submit a review on this public repository, and `authorAssociation` cannot be used because private organization members appear as `NONE` to the workflow token;
- the PR has no `needs-acceptance` label;
- CI has run on that head and every other check succeeded.

While checks are running or the PR waits for acceptance, the workflow exits without merging and a later event retries. When a check fails, it comments once per approved commit with the failing checks. Open UI-bearing PRs with the `needs-acceptance` label; the architect removes it after the user accepts the UI. Merges made with `GITHUB_TOKEN` do not start push workflows, so the workflow dispatches `ci.yml` on `main` after merging. Branch protection is configured separately in the repository settings.

Review and label events (`pull_request_review`, `pull_request: unlabeled`) run the workflow definition from the PR's merge ref, while CI completion (`workflow_run`) runs the definition on `main`. A PR whose branch predates a change to `auto-merge.yml` may therefore get no run, not even a skipped one, when it is approved or its label is removed. Update the branch from `main` (for example with GitHub's Update branch) so the next review or label event runs the current workflow; the next CI completion also retries the merge.

## Scope of evidence

The UI rules above describe the current product behavior. Local build and automated checks do not establish visual interaction, iPhone import/upload or compatibility with a particular chat client. Those outcomes require their own acceptance evidence. Report actual validation results and distinguish automated checks from hands-on acceptance.

## Naming

Use `com.cuxiao.mac.anydock` for the bundle identifier, Logger subsystem and preferences domain. Preserve existing preference keys, including copyNewItems. The connection configuration file (`Application Support/AnyDock/configuration.json`) holds `ConnectionConfiguration`: `receiver` (port, token, receive folder) and `sender` (personalized shortcut name, saved only after a successful send). Keep configured receive paths unchanged; fresh installations use ~/Downloads/AnyDock. Never log configuration bytes or keys. Received files use the `AnyDock-` prefix; `InboxStore.list` includes only `AnyDock-` items, and recycling uses that same set. Uploads authenticate with the `X-AnyDock-Key` header. Product names are localized as AnyDock in English and 随手坞 in Simplified Chinese.
